# 项目文档维护

按 [文档规范](../../docs/engineering/documentation/README.md)选择需要读取的类型。规范定义内容边界；本技能负责执行，不复制模板与规则。

1. 确认本次变化的事实、读者与正式维护位置。已有同义文档先更新原文件，不另建“新版”“原件”或来源快照。命名及类型不明时沿用现有模块导航；关键范围不明再澄清。
2. 层 README、模块接口、组件说明分别读取规范目录中的相应模板；ADR、Issue、计划、教训读取 [记录规范](../../docs/engineering/documentation/records.md)。只加载本次相关类型。产品/架构/部署变化从 [项目导航](../../docs/README.md)找到原文件更新。
3. 从实际代码、测试、接口及已接受决策核对内容；资料不足明确待验证。决策改为新方案时，标记被替代条款并互链，不能把历史记录当当前命令，也不能让代码偏差自动改变契约。
4. 修改唯一正文；同步受影响的父导航、入链链接和适用 ALIGNMENT 行。移动文件后更新 Markdown 链接及文中实际路径；若脚本依赖旧路径，先核验脚本，不能靠保留第二份文档规避。新文档类型才扩展根 AGENTS 路由。
5. 检查链接/锚点、正式位置唯一、类型所需内容和证据状态。完整仓库中按 [部署文档](../../docs/project/deployment.md)运行适用校验；缺少源码或脚本时报告未执行，不补造通过记录。

交付说明改了哪份正式文档、影响哪些引用、做了哪些检查及仍缺什么证据。纯文档任务不扩大成代码修复或部署；写入前按 [项目工作流](../../docs/engineering/project-workflow.md#planning)输出方案并获得确认。更新计划与评审，真实纠正形成可复用经验时更新 lessons 并链接正式规则。
