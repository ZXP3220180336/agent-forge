# 文档迁移的引用与来源核对

日期：2026-09-12。状态：仓库引用已修复；外部规范来源待提供。优先级：P2。发现来源：治理包合入后的文档核查。范围：文档迁移，不涉及业务实现。

## 现象与根因

离线资料缺少源码时，43 处真实源码或测试链接被替换为“未随资料提供”，另有 3 处 Markdown 字面示例被误当作文件链接。接入完整仓库后继续保留这些说明会阻断导航；问题根因是材料包证据边界未随接入状态更新。问题总索引还重复了四组导航，未接入文档问题目录。

## 方案与实施

沿用[单一来源 ADR](../../adr/2026-09-12-single-source-governance.md)和[文档维护规范](../../docs/engineering/documentation/README.md)：对照实际目标恢复 43 处链接，修正必要的相对层数；3 处示例恢复为行内代码；总索引去重并补充文档问题导航。保留原文件归属，不复制规范或源码。此项为本地引用与措辞修复，不改变技术契约，无需新增外部方案选型。

## 验证

对正式文档执行本地文件目标、标题及显式锚点检查，并从 AGENTS 检查导航可达性；文档映射与差异格式检查结果见[迁移说明](../../docs/migration.md)。这些检查不证明业务行为符合全部治理要求。

## 外部来源边界

用户指令要求遵守 `编码规范文档.txt`。本轮搜索仓库（含隐藏文件、排除 Git 内部目录）未找到该文件；现有 `docs/shared_doc/encoding.md` 是字节编码工具说明，不是其替代品。该外部来源仍待提供文件或有效位置，未宣称其已迁移、已执行或已被废止。

此缺口保留在本记录，不阻塞已提供文档的目录与引用迁移。未来代码任务涉及该规范时，须先取得来源；本轮不编写替代规范或改动代码。

## 教训

材料包中的“未提供”描述只适用于当时资料范围；接入仓库后应以目标存在性恢复导航，同时保留业务测试未运行的真实边界。经验入口见 [lessons](../../docs/lessons.md)。
