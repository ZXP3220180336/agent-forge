# 通用 AI 工程治理规范

本规范管理代码变更的正确性、结构和证据。Agent 领域细节见 [运行时规范](agent-runtime-rules.md)。项目边界、工作流与集成检查分别见 [项目边界](../project/architecture.md)、[执行工作流](project-workflow.md)、[集成规则](integration-rules.md)。实现状态由对齐表管理，治理目标与实现证据分别记录。

<a id="levels"></a>
## 1. 等级与判定

| 等级 | 含义 | 执行与例外 |
|---|---|---|
| G0 | 正确性不变量 | 适用时必须成立，不能以便利豁免；不适用须有事实依据 |
| G1 | Trigger 命中后的强制检查 | 不能跳过检查；可以得出无需重构的结论 |
| G2 | 维护性审查信号 | 评估受影响结构，允许保留现状并简述理由 |
| G3 | 设计偏好 | 按上下文取舍，不作为阻断依据 |

等级描述规则强度，不等于缺陷严重度。多个 Trigger 可以在一次分析中合并检查，同一证据不重复生成。

<a id="review-criteria"></a>
通用评审覆盖逻辑正确性、边界条件、异常捕获、性能、安全与可读性，并按任务涉及的行为和影响提供证据。G0 与 Gate 是专项检查，不替代这些通用评审维度。

Gate 输出是可验证的结论与必要依据，不要求公开逐步推理。通常只记录命中的 Gate、结构决定和验证结果。架构变化、范围扩大、契约变化、多种方案需要取舍或用户要求计划时，显式说明方案。写前方案确认和测试要求按 [项目工作流](project-workflow.md)执行，Gate 不豁免这些要求。

<a id="g0"></a>
## 2. G0：七项不变量

### G0-1 自动执行有界

一次运行中的循环、重试、修正、fallback 必须有可证明的停止条件：有限次数、有效截止时间、严格递减预算或等效条件。不能依赖“最终会成功”。长期服务可持续运行，但单次工作、等待和重试须受预算或可执行的取消/关闭契约控制；本规则不要求永久服务自动退出。

### G0-2 终态关闭业务准入

已决定的成功、失败、STOP、取消、超时等终态，关闭本次运行的新业务副作用准入。必要的结算、资源释放和 best-effort 观测允许执行，但必须有界且不能偷偷启动业务 fallback。取消请求尚未生效与终态已经提交应明确区分。终态不能撤销远端已经开始的操作，其迟到事实仍按 G0-3/G0-4 接管。

### G0-3 唯一逻辑结算

每个 usage、reservation、transaction、stream 或其他资源的结算责任必须明确，所有权转移不能出现无人负责或双方同时结算。一个结算单元只能从未结算进入一个确定的最终结算状态一次。允许重复调用幂等 cleanup/settle，不能产生第二次账务效果。增量流按唯一增量或最终差额结算，不能将累计快照重复相加。

### G0-4 事实一致性

终止可以阻止提交、舍弃临时表示，但不得导致已知 usage 漏记、已确认副作用被当作未发生、资源失去结算责任，或契约认可的可用成果被无条件清空。未知事实标记为未知，交由明确的恢复/核对责任处理。本规则不要求保存完整 SDK 对象、所有字段或敏感原始数据；保留必要、合法且可追踪的事实即可。

### G0-5 协议合法性

本地已确认违反当前适用协议的请求或历史不得发送。先在本地修正、隔离或终止；未知服务端约束仍可能报错，不要求预测全部远端行为。

### G0-6 观测隔离

日志、metrics、tracing 等非业务关键观测的失败不能替换主业务异常或终态，也不能无限阻塞收尾。若审计持久化本身是业务成功的必要条件，必须将其明确建模为提交前置条件和失败语义，不能伪装成 best effort；已提交的终态不由事后观测重写。

### G0-7 不确定副作用不能盲目重放

本地超时、断连或取消不证明远端未执行。重试前须有适用的幂等键、去重、查询核对或明确的重复执行处理契约；无法安全重试时停止自动重试并保留不确定状态，不伪造成功或失败事实。

<a id="gates"></a>
## 3. G1：Trigger → Gate

| ID / Gate | Trigger | 必要检查及通过证据 |
|---|---|---|
| E1 Complexity | 同时增加状态、控制流、副作用、生命周期、错误语义中的至少两维 | 列出变化与受影响职责，判断现有边界是否足够；解释采用的最小结构变化 |
| E2 Large Orchestrator | 大型或认知复杂的编排方法新增状态、分支、重试或异常路径 | 确认编排仍表达阶段与转换；识别泄漏的解析、计数、结算等细节，不因长度自动拆分 |
| E3 External Call Lifecycle | 新增或修改 SDK、HTTP/RPC、数据库事务、工具、消息、文件副作用 | 明确准入、调用中责任、响应接管、结算、失败和下一副作用的许可；不适用阶段说明原因 |
| E4 Retry | 新增或修改自动重复执行或 SDK 内置重试配置 | 明确次数语义、Owner、边界、重置、可重试错误、停止结果、等待策略和全局预算；检查重复执行风险 |
| E5 Ownership | 修改响应、usage、reservation、stream、事务、partial result 等生命周期状态 | 明确创建、接管、转移、正常与异常结算责任；证明每条退出路径均有 Owner |
| E6 Error Boundary | 新增或修改捕获、异常转换、fallback、错误策略、终态分类 | 明确来源、解释层、恢复层、终止层与诊断路径；排除重复捕获和不可达分支 |
| E7 State Machine | 关联状态跨步骤修改，生命周期或一致性难由局部作用域表达 | 列出合法转换和修改者；优先局部变量/现有对象，只有必要时引入状态对象 |
| E8 Regression | 修复 Bug 或改变既有控制流语义 | Bug 先建立失败复现，再修复并验证；控制流变更验证新旧契约差异、相关边界和异常路径 |
| E9 Abstraction | 准备引入新类、接口、协议、Policy、Manager、Handler、State 或抽象层 | 按下一节证明现有边界不足以及新抽象的真实价值 |

追加 Gate 以实际变化为准：新外部调用不自动要求设计 retry；有重试才触发 E4，有资源所有权变化才触发 E5。Agent 外部调用的细化见运行时规范。只审查任务涉及的结构，不借机清理全库。

E6 要求异常根因在诊断边界内可追踪，例如异常链或关联记录；不要求领域 API 暴露底层异常对象。取消、截止时间和程序缺陷不得统一吞成可重试服务错误。顶层通用捕获可作兜底，不能承担全部业务分类。

E8 优先采用确定性的回归测试。环境无法复现时，报告实际阻碍与替代证据，不能声称失败测试已运行；依据项目验收要求决定是否仍有阻断。纯措辞、格式等低影响变更使用相应检查，不机械增加行为测试。

<a id="abstraction"></a>
## 4. 最小结构变化与 Abstraction Gate

最小结构变化不等于最小 diff。先在现有职责内正确实现；其次考虑有明确语义的小范围方法提取；只有现有边界不足时，才考虑新架构对象。

新增抽象至少需要以下一个真实理由，并解释其收益为何超过引入的耦合和维护成本：

1. 有独立生命周期。
2. 有独立状态所有权。
3. 有独立且正在增长的变化原因。
4. 有两个以上真实调用方，共享的是同一语义。
5. 承担可独立测试的重要策略。
6. 现有方法无法在同一抽象层清晰表达该职责。

“代码长”“为了 SOLID”“以后可能复用”“看起来清晰”“缩短 execute”单独均不充分。满足一项也不自动要求抽象。

方法提取应形成业务语义、状态转换、细节隐藏或真实复用；不制造仅搬运参数的转发链。多个局部变量并不自动要求 RunState；跨方法共同修改、成组传参、异常补偿和一致性约束才是重要证据。State 不能变成万能参数包。

必要的结构调整限于本任务的直接依赖边界，先以测试保护既有行为，再引入行为变化。不顺手重构，也不以最小 diff 掩盖职责持续恶化。

<a id="indicators"></a>
## 5. G2：维护性信号

以下为沿用讨论的参考区间，项目可按语言和代码类型调整；它们不是 lint 硬限制，也不自动触发重构：普通方法约 40–60 行、编排方法约 80–120 行、类约 300–500 行、文件约 500–800 行、嵌套超过 3 层、参数超过 5–7 个、关联状态超过 5–8 个。

多个独立重试计数器、多个终态出口、多种副作用、不同需求反复修改同一方法的不同区域，也是信号。生成代码和声明式数据按性质判断，不机械套用行数。

命中后检查变化原因、认知负担与隐藏状态机。保留现状可以用一句话记录，例如：“保持当前方法：流程线性、状态局部，拆分只会增加参数传递；新增共享状态时重审。”不要求每次提交统计全库行数。

## 6. G3：设计偏好

默认偏好有语义的方法、清晰命名、较少嵌套、组合、显式状态与合适的不可变值对象。以当前契约和维护成本为依据，不为偏好改写无关代码。具体格式和语言规范归项目编码规范维护；用户指定文件的来源状态见[规范来源核对](../../issues/documentation/2026-09-12-reference-gaps.md#外部来源边界)。

## 7. 完成证据与规则维护

完成时核对适用 G0、命中 Gate、验证结果、范围与契约变化，报告未验证项和实际阻断。测试通过不替代结构判断；结构看起来清晰也不替代正确性证据。

入口只摘要和路由；本文件是通用规则唯一正文，运行时文件只作领域细化，Skill 不重抄规则。历史 ADR、Issue、lessons 是判断依据，未经确认不自动升级为强制规则。发现正文、局部规则与现行契约冲突时，指出冲突条款和受影响路径，按有效指令和已确认决策处理，不能擅自宣称旧规则废止。

规则修改遵循 [文档维护规范](documentation/README.md)；治理裁决与实现缺口见 [治理决策](../../adr/2026-09-12-single-source-governance.md)。不得建立原文快照作为第二套日常规范。
