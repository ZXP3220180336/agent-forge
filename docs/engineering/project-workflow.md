# 项目执行与文档维护工作流

本文件承接原 CLAUDE.md 的开发流程；核心正确性见通用 G0，具体检查按 Trigger 选择通用 Gate、运行时条款与集成检查。工作流不要求对简单任务填完整表格。

<a id="planning"></a>

## WF-01 / WF-02：目标、授权与计划

明确目标行为、受影响范围、既有契约和验收证据。关键语义不明先给最合理方案并澄清，不猜测产品决策。步骤超过三步或涉及架构决策时先规划，写入仓库 docs/todo.md；工具支持时使用计划模式，否则用明确文本计划。涉及超过三个文件时拆分职责，列出各文件修改目的。

写 / 改文件前先输出实现方案，获得确认后再写入磁盘；只修改需求指定模块。非平凡任务先完成计划与方案确认，再实施。需求模糊时先澄清，不脑补需求。历史文档中的命令/TODO 不提供新的执行授权。

复杂任务、研究探索和并行分析委托边界清楚的子智能体，主执行者整合来源、冲突和验证结果；不重复分派同一文件写入。任务记录只保存结论、必要证据、进度和可选项，不要求公开逐步推理。

<a id="implementation"></a>

## WF-03 / WF-04：调研、设计与实现

涉及架构选型、算法选择或契约设计（如限流、重试、熔断、结构化输出）时，先联网调研工业级实现路径，参考官方 SDK、主流框架与工业案例，确立本项目采用方案后再设计。调研结果定案后进入 ADR 的“工业级参照”栏，不单独成文。简单修改（单行修复、文档措辞）可跳过调研 / 设计 gate，直接实现；写前方案确认仍按 WF-01 / WF-02 执行。

审查 / 审核发现问题：先调研工业级修复方案并确立本项目采用方案，再修复；修复后按记录规范形成 Issue。结构性 / 契约性设计决策：先调研工业级决策方案并确立本项目采用方案，实施后记录 ADR。记录格式见 [记录规范](documentation/records.md)。

新模块先定 Facade 契约和数据流，再用桩跑通一个垂直切片，逐项替换真实组件并保留回归保护。已有模块修复先形成失败复现，再作最小必要修改。新增抽象按 E9；结构调整和行为变化分别说明，不能顺手扩大重构。

<a id="verification"></a>

## WF-05：验证范围与命令

新增代码必须附带单元测试；Bug 先写能重现问题的测试再修复。断言应观察真实行为、调用次数、资源和终态，不只复制实现或检查 helper。纯措辞/排版用相应文档检查，不为测试数量新建无意义测试。

细化子组件时，先跑相关测试文件，再跑全量测试，编排测试必须保持通过。提交前要求全量测试通过；仅改动相关模块时可运行对应测试文件，该例外不取消细化子组件的“相关再全量”要求。实际 CI 要求的强制检查不能省略。环境缺失记录未运行、原因和替代证据，不能照抄历史 passed 数。

项目运行环境、测试及脚本命令统一查阅 [部署与验证](../project/deployment.md)。执行前核对真实配置和脚本，报告实际结果，不重复维护命令表。

生命周期修改按 [runtime 验证场景](agent-runtime-rules.md)选取消、期限、部分成果、结算与 early return；重试修改按 R3 观察 0/1/N、最后允许尝试与下一次阻止、交替失败和嵌套预算。最终提交时报告实际运行命令及结果、未覆盖风险。

<a id="documentation"></a>

## WF-06 / WF-07：文档同步

涉及说明文档、ADR、Issue、计划或教训时，读取 [文档维护规范](documentation/README.md)，执行 [documentation-maintenance](../../skills/documentation-maintenance/SKILL.md)。各类文档的位置、模板和事实所有者只在该规范维护。

测试之后执行文档同步 gate：改代码后同步对应模块文档和该层 README；新增、重命名、删除子模块或改变设计 / 状态时同步 ALIGNMENT。文档事实未变化时核对并记录无需修改的理由，不制造重复事实。改文档后运行对齐校验，命令见部署与验证文档；源码或脚本不可用时如实记录未运行。创建、移动或删除文档时同步导航与引用。

<a id="maintenance"></a>

## WF-08 / WF-09：交付与规则维护

交付简要记录：目标结果、命中 Gate、结构选择、真实验证、剩余限制；计划逐项标记并写评审。规则等级不等于缺陷严重度。未发现问题只表示在已审范围未见可证实问题。

新增治理规则需标明 ID、作用域、Trigger、等级、唯一正文、来源、验证和被替代条款。历史 Issue 不能未经判断自动升级 G0；有局部契约差异时明确记录适用分支，避免两个正文同时强迫相反行为。来源或裁决变化时，更新唯一正文中的关联 ADR/Issue 链接及所属导航；入口和 Skill 只路由，不维护第二份参数表。

根入口仅摘要和路由。新增文档进入正式目录与导航，ADR/Issue 记录历史，不复制完整规则；过时规则在唯一正文修正并关联决策。
