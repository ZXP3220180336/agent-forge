# 模块对外接口文档设计规范

适用于单个模块的公开契约文档，如 `app/integration/llm/` 对应 `docs/integration_doc/llm_doc/llm.md`。共用的事实判定、状态、配置、示例、格式和验证规则见[工程文档维护规范](README.md)；本文件只规定模块外部调用面的内容。

## 定位与命名

读者是其他层或模块的调用方。文档回答“模块承诺什么能力、如何调用、如何处理失败”，由公开契约与内部组件导航组成，不展开内部算法。

沿用 `docs/<layer>_doc/<module>_doc/<module>.md`；层总览仍为 `docs/<layer>_doc/README.md`，组件说明一般按组件主题或对应源码文件命名。单一简单模块仍使用模块名，不因没有组件子文档而换成第二类 README。

## 公开契约的边界

公开面由领域端口、公开 Facade、明确导出与已接受的调用约定确定，不是所有可见 Python 方法，也不只是当前引用搜索命中的方法。无当前调用方但仍公开承诺的接口可以保留，使用情况和实现/接线状态链接 ALIGNMENT；不得为降低文档量擅自删除该承诺。

只被 Facade 内部消费的 `ClientManager.get_client` 等组件方法不进入模块公开方法表。装配根、测试或异常跨层引用应核对其合法性；发现对内部组件的越界调用时记录差异，不能直接把它升格为公共 API。`_` 前缀是私有性的线索，最终仍以明确的模块边界为准。

## 内容要求

- **接口**：准确列出公开方法的同步/异步形态、签名、参数含义、默认值、返回结构及必要的副作用/资源责任。复杂数据结构可链接其唯一契约位置。
- **错误与终止**：说明哪些失败抛异常、哪些返回 `None` 或失败结果、哪些经事件外显。需要时覆盖取消、超时、部分成果及用量字段；不假定各入口异常语义相同。
- **最小调用示例**：只经认可的外部接口演示典型调用和必要结果处理，不绕过 Facade 调内部实现。
- **内部导航**：每个相关组件给职责、文件和说明链接；状态机、重试/结算细节及算法进组件说明，决策取舍链接 ADR。
- **配置关联**：解释配置影响哪种公开能力，完整键表链接配置参考。

## 建议模板

```text
# <模块名>对外接口文档
> 对应代码：app/<layer>/<module>/
> 文档定位：模块公开契约与组件导航
> 更新日期：<本次编辑日期>
> 状态与映射：<指向 docs/ALIGNMENT.md 对应条目>

## 目录
按文档长度决定是否需要。

## 模块概述
核心能力、边界、必要结构与依赖导航。

## 对外接口
| 方法/符号 | 同步/异步 | 参数与默认值 | 返回及调用语义 |
列公开 Facade、领域端口或明确导出；链接复杂数据契约。

### 错误与终止契约
| 触发条件 | 异常/返回/事件 | 调用方责任 |
包括本模块公开承诺的失败、取消、部分成果或资源语义。

### 最小调用示例
通过公开入口调用及必要的结果处理。

## 内部实现导航
| 组件 | 代码位置 | 职责 | 组件说明 |

## 配置关联
配置如何影响本模块能力及配置参考链接。

## 相关文档
层 README、契约类型、必要的 ADR / Issue 和组件说明。
```

## 本类型的核对重点

外部契约变更应逐项核对端口、Facade、调用方、示例和测试。引用搜索帮助定位影响范围，不能单独裁决公开性。新增、移除或更名文档时核对层 README 与 ALIGNMENT 的映射；只改变内部实现且对外语义不变时，不需要在接口文档复述修复经过。

内部协作接口见[组件规范](component_doc.md)，全层地图见[层级 README 规范](layer_readme_doc.md)。维护操作与验证流程统一执行 [README 中的维护入口](README.md#维护与验证入口)。
