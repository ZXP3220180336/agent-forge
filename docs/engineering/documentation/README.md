# 工程文档维护规范

本目录是项目文档写作规则的统一入口。先按读者选择文档类型，再读取相应模板；具体维护步骤、任务记录与验证由[文档维护技能](../../../skills/documentation-maintenance/SKILL.md)统一执行。

## 文档分工

| 文档 | 回答的问题 | 内容归属 |
| --- | --- | --- |
| [层级 README](layer_readme_doc.md) | 这一层有哪些模块、如何协作、从哪里进入？ | 层边界、模块地图、主调用链与导航 |
| [模块接口文档](module_doc.md) | 模块承诺什么能力，外部怎样调用？ | 领域端口或公开 Facade 的调用契约、外部错误语义与最小示例 |
| [组件说明](component_doc.md) | 模块内部怎样协作、维护时哪些边界不能破坏？ | 内部协作契约、算法及状态语义、资源责任和验证入口 |
| [ALIGNMENT](../../ALIGNMENT.md) | 实现、接线、文档和测试处于什么状态？ | 当前状态及代码—文档—测试映射的唯一主位置 |

层与模块文档的路径继续沿用 `docs/<layer>_doc/`，不因写作规范集中到本目录而搬动整套项目说明。

## 事实、契约与证据

代码、测试和契约回答不同问题：源码体现当前实现；测试及其运行结果提供特定条件下的证据；已接受的接口、产品和 ADR 契约描述承诺的行为。发现三者不一致时，应记录差异、影响和待核实项，按变更流程判定是修复实现、修正文档还是迁移契约。不能仅因为代码当前如此就静默改写承诺，也不能把文档声明当作代码已验证。

公开接口的识别结合领域端口、导出约定、配置装配、已接受 ADR、使用示例和实际调用方。引用搜索用于发现使用情况；没有当前引用不自动取消公开承诺，有跨模块引用也不自动证明该依赖符合架构。

只在 [ALIGNMENT](../../ALIGNMENT.md) 维护当前实现、接线及验证状态。层、模块、组件文档用链接指向相应条目，不再手工复制状态徽标或测试通过计数。为解释契约而提及“当前未接线”“仅参考实现”等边界时，引用状态条目并在维护时核对；它不是第二份状态清单。文档更新日期只表示本次编辑日期，不等于实现或测试通过日期。

没有源码、测试、依赖或执行环境时，可以核对文档之间的一致性并整理待验证契约，但应明确证据缺口。不得写“源码已对齐”“测试已通过”或“已运行 verify_alignment”。引用历史验证应注明其为历史记录，不将旧测试数量作为当前覆盖证明。

## 一个事实一个维护位置

- 签名、输入输出、错误和调用语义集中在相应契约位置；其他层级只摘要并链接。组件内部协作契约不在模块 Facade 方法表重复展开。
- 配置键的完整表、默认值、取值约束和生效方式只在配置参考维护。模块或组件可以解释“配置如何影响本能力”，并链接具体配置项；不再维护独立完整表或复制定价常量。
- 当前说明写当前有效行为；替代关系、理由和历史修复分别链接 ADR、Issue。修订 ADR 时明确哪些条款被替代，不把整份旧文档无条件当作当前规则。
- 删除重复内容前，先确认保留位置完整、可达且语义一致。涉及事实未变化时记录“已核对，无需修改”，不为满足流程机械改文档。
- 只链接读者理解本契约所需的相关内容。相关性也包括共享协议、数据流、安全或生命周期边界，不仅是直接 import；不要重复介绍无关模块。

## 表达与示例

正文使用中文，标识符、路径和协议术语保留原名。契约参考与设计解释分节：先让读者找到调用语义，再解释必要的理由；已存在 ADR 时优先链接，不复制备选方案全文。

结构 / 依赖图代码块一律指定 `text` 语言，使用文本结构图表达；目录树、ASCII 图和伪代码同样使用 `text`。可执行示例使用对应语言围栏，所有围栏标语言。图的目的与正文互补，简单关系无需为模板强行画图。

不完整复制生产实现。允许最小调用示例以及解释关键不变量的短片段；示意片段标注“示意”并指向实现符号，不能伪装成可直接运行的完整实现。学习性参考实现须明确未接入生产，并确认其唯一维护位置；不能一边在源码保留同一实现，一边宣称文档是唯一载体。

模板是覆盖检查提示，不是固定章序、行数或方法数量门槛。短文可省目录与不适用章节；复杂文档按读者需要调整顺序。决定篇幅的是契约与风险，不为凑章节、方法数或 LOC 拆文档、增代码。

## 维护与验证入口

涉及结构、路径、公开契约、配置、行为边界或接线状态的变更，按[文档维护技能](../../../skills/documentation-maintenance/SKILL.md)检查对应位置及入链链接。具体类型需要覆盖的内容见下列模板，执行步骤不在三份模板重复维护。

验证至少区分：文档结构与链接检查、契约和实现核对、测试运行证据。具备完整仓库且脚本可用时，按项目检查要求运行 `uv run python -m scripts.verify_alignment`；它通过只证明其实际检查范围，不自动证明业务契约全部成立。缺少执行条件时列明未执行项与原因，不补造通过结果。
