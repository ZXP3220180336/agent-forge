# ADR、Issue、计划与教训记录规范

通用事实、状态、格式和单一维护原则见 [文档规范](README.md)，执行步骤见 [文档维护 Skill](../../../skills/documentation-maintenance/SKILL.md)。本文件是记录类文档的唯一写作规范；各目录 README 只导航，不复制本规范。

## ADR：选择与取舍

一个决定一个文件。主决策模块明确时放 `adr/<层>/<模块>/<YYYY-MM-DD>-<短描述>.md`；无单一归属的横切决定放 `adr/` 根目录。ID 沿所属索引既有序列；新文件不把 ID 强塞进文件名。

正文包括：标题及日期/状态/范围、Context（问题、约束、真实备选和工业级参照）、Decision（采用方案及适用范围）、Consequences（收益、代价、升级触发条件）、实现与验证证据、关联记录。

**决策状态与实现状态分开**：待讨论、已接受、被部分/全部替代、已放弃描述决定；待实施、实施中、已验证描述兑现。旧记录“已采纳”徽标保留其历史语境，不能据此宣称所有条款当前已实施。替代时指出具体条款和后继链接，保留理由，不改写历史为当前事实。新决定更新所属索引；模块说明只写当前有效契约并链接决定。

## Issue：问题闭环

一个根因一个文件，路径 `issues/<层>/<模块>/<YYYY-MM-DD>-<短描述>.md`。跨模块按主因归位；文档体系自身问题放 `issues/documentation/`。编号沿既有模块序列，不复用旧编号。

正文包括：状态/优先级/发现来源/范围；现象与影响；可复现条件及证据；根因；方案与取舍；实施记录；验证结果；可复用教训和关联文档。调研、方案定案与实施先后顺序按 [项目工作流](../project-workflow.md#implementation)执行，记录采用方案的工业级参照。没有源码证据时标“待核验”，不能断言已发现生产 Bug。

状态可用待核验、待修复、修复中、已修复、口径记录、已放弃。已修复须有该问题的实施与验证证据；本轮文档引用历史已修复记录不代表重跑。P0–P3 表达影响与紧迫度，不由 G0–G3 自动推导。修复中若改变设计契约，另立 ADR；仅发生实现修复不强制产生 ADR。

## todo：当前工作

固定位置 [docs/todo.md](../../todo.md)。记录当前目标、授权边界、拆分步骤/文件、验收、进度和评审；可选项与未授权候选分开。已完成的问题详情链接 Issue，不复制其完整生命周期。

完成事项不长期混在活动清单。值得保留且无其他归属的独特交接结论移入 [完成记录](../../history/completed-work.md)，仅保留结论与指向正式文件的链接，不建立 todo 全量副本。旧未勾项已被后续完成记录覆盖时从活动清单移出。

## lessons：纠正后的经验

固定位置 [docs/lessons.md](../../lessons.md)。每条简述适用 Trigger、已证实教训、正式规则与来源；重复教训合并。规则正文已有完整约束时只链接，不再抄写参数表和强制检查。一次局部修复不自动升级为全局规则；被后续证据修正的经验删除失效结论，保留必要的更正链接。

## 示例骨架

```text
# <决策或问题标题>
日期 / 状态 / 范围 / 关联
## 背景或问题
## 决定或修复方案
## 代价与未覆盖边界
## 实施与验证
## 关联记录
```

按文档类型补充真正必要的内容，不要求所有记录拥有相同章序、长度或无意义的占位章节。
