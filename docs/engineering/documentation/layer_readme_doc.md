# 层级 README 写作规范

适用于 `docs/<layer>_doc/README.md`，对应 `app/<layer>/`。共用的事实判定、状态、配置、示例、格式和验证规则见[工程文档维护规范](README.md)；本文件只规定层总览的内容。

## 定位

层 README 服务跨层浏览者，回答“这一层负责什么、包含哪些模块、如何协作、下一步读哪里”。它是层地图与导航，不承担模块 API 详情或组件实现说明。

## 内容要求

1. **层边界**：用简短说明交代本层职责及必要依赖方向；分层依据链接[架构说明](../../project/architecture.md)，不复制全部项目架构。
2. **模块地图**：列模块、代码位置、职责及主文档链接。目录树帮助定位时再添加；文件细节留在模块说明。
3. **子系统导航**：每个重要子系统给一句职责与入口。可用统一模块表，也可分别设节；避免两处重复同一清单。
4. **主调用链**：选择一条能说明跨模块合作的典型链路，标清每一环职责和边界。异常流程、恢复状态机等细节链接组件文档。
5. **状态与配置入口**：状态指向 `docs/ALIGNMENT.md` 对应层或模块条目；配置仅给“模块能力 → 配置参考”导航。

## 建议模板

```text
# <层名>说明文档
> 对应代码：app/<layer>/
> 文档定位：层总览与导航
> 更新日期：<本次编辑日期>
> 状态与映射：<指向 docs/ALIGNMENT.md 对应位置>

## 目录
按文档长度决定是否需要。

## 层定位与边界
核心职责、必要依赖方向、架构说明链接。

## 模块地图
| 模块 | 代码位置 | 职责 | 主文档 |
目录树可选；不复制逐组件状态表。

## <重要子系统>
仅在统一模块表不足以说明时添加：一句职责、入口与必要设计要点。

## 典型调用链
外部调用方 → 模块入口 → 协作模块，标明各环节职责。

## 配置关联
模块能力与配置参考的链接。

## 相关文档
架构说明、必要的模块说明及状态映射。
```

## 本类型的核对重点

检查层内模块的新增、移动、重命名、删除是否反映在地图和链接中；检查调用链是否表达当前认可的依赖方向，是否误把未接线能力画成已运行主链路。结构或文档位置变化时更新父级导航及 ALIGNMENT 映射；只改组件内部实现且层边界未变时，核对后可保持层 README 不变。

模块 API 应移交[模块文档](module_doc.md)，模块内部机制应移交[组件文档](component_doc.md)。维护操作与验证流程统一执行 [README 中的维护入口](README.md#维护与验证入口)。
