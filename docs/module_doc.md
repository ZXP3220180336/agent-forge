## 一、定位与目标

模块对外接口文档（如 `llm.md`）说明**一个模块（`app/<layer>/<module>/`）对外的
接口契约**。服务对象是模块的**外部调用方**（其他层 / 模块的文件）——回答「这个模块
对外提供什么契约、怎么调用」，不回答「内部怎么实现」（那是组件子文档与 ADR 的职责）。

**目标**：契约可查、调用可上手、与代码零漂移。它是「模块 Facade 的接口契约 +
内部组件导航」二合一文档。

## 二、与其他文档的分工

| 文档 | 层级 | 回答 | 读者 |
| --- | --- | --- | --- |
| 层 README | 层（`app/<layer>/`） | 这层有哪些子模块、怎么串 | 全局导航 |
| **模块对外接口文档** | 模块（`app/<layer>/<module>/`） | 这个模块对外提供什么接口、怎么调用 | 外部调用方 |
| 组件子文档 | 组件（模块内单个 `.py`） | 组件怎么设计、边界、决策 | 内部维护者 / 集成方 |

**边界**：模块对外接口文档只写「模块对外的契约 + 内部组件导航」，不写组件实现细节
——双处维护必然漂移（Rule 1「一个事实一个家」）。

**命名约定**：模块对外接口文档文件名 = **模块名**（与源码目录对应，如
`app/integration/llm/` → `llm.md`），路径镜像源码结构
（`app/<layer>/<module>/` ↔ `docs/<layer>_doc/<module>_doc/<module>.md`）。
**层 README 保留 `README.md`**（`docs/<layer>_doc/README.md`）——避免「README.md」
一词多义（既是层总览又是模块文档），三级命名递进自洽：
层 README（层名 + README.md）→ 模块文档（模块名）→ 组件子文档（源码文件名）。
单一简单模块（目录无组件子文档）仍用模块名，保持一致。

## 三、编写原则

1. **读者 = 外部调用方**：核心是 Facade 的对外接口契约（方法签名 / 参数 / 返回 /
   异常 / 最小调用示例）；内部机制进组件子文档与 ADR。
2. **对外接口 = 外部文件依赖的接口**：只列被外部文件（其他模块 / 层）引用的接口——
   模块对外通常是 Facade 类的方法（如 `generate` / `async_generate` /
   `generate_structured`）+ 被外部捕获的异常类型。**由 Facade 内部依赖的子组件接口
   （如 `ClientManager.get_client`）不属对外接口**，只做导航链接。公共方法均可列，
   `_` 前缀私有方法 / 内部辅助函数不列（放组件子文档）。
3. **Rule 1：不搬子文档内容**：组件细节（状态机、降级链、算法、配置全表、定价表）
   只在组件子文档；模块文档给「组件表 + 一句话职责 + 链接」。
4. **Rule 2：写当前状态，不写历史**：只描述当前存在的接口 / 组件 / 契约；演进叙事
   （日期标记、修复记录、重构）归 git commit + issues + ADR。
5. **配置只做导航**：配置项完整表在组件子文档 / 配置文档；模块文档给「配置 → 能力」
   的指向，不复制全表。
6. **契约准确性**：接口签名、默认值、异常与对应 `.py` 当前代码一致。

## 四、标准结构

```text
# <模块名> 对外接口文档
> 元信息引用块：对应代码 / 更新日期 / 文档定位 / 实现状态（可选：配套）

## 📋 目录

## 模块概述
  核心功能一句话 + 模块结构树（text 代码块）+ 设计原则 + 依赖关系

## 对外接口
  Facade 方法表（| 方法 | 同步/异步 | 说明 |）+ 参数 / 返回 / 异常契约
  + 最小调用示例；对外异常契约表（被外部捕获的异常 → 触发 → 调用方处理）

## 内部实现组织
  子组件表（| 组件 | 文件 | 职责 |）——每个组件链接其子文档 / ADR，不展开实现

## 配置关联
  配置 → 能力的导航（全表在组件子文档 / 配置文档）

## 相关文档
  层 README + 组件子文档 + ADR + issues
```

### 结构要点

1. **对外接口聚焦 Facade**：只列模块对外暴露的公共接口（被外部文件依赖）；内部组件
   接口不在此栏，只做导航。
2. **内部实现组织 = 导航表**：每个子组件一行「职责 + 链接」，不搬子文档内容。
3. **调用示例最小化**：只演示对外接口用法，不含内部实现细节。
4. **状态对齐代码**：接口 / 组件状态与当前 `.py` 一致；结构图代码块指定 `text`
   语言，禁止裸代码块。

## 五、创建 / 优化流程

1. **核对代码**：接口签名、默认值、异常、子组件清单全部以当前 `app/<module>/` 为准
   （不凭记忆）。
2. **判断外部接口**：grep 其他文件对模块的引用，确认哪些是外部文件依赖的接口
   （Facade 方法 + 外部捕获的异常）。
3. **契约优先**：先写对外接口，再补模块概述与内部导航。
4. **同步引用**：更新层 README 的模块链接、ALIGNMENT.md、CLAUDE.md 文档体系。
5. **校验**：跑 `uv run python -m scripts.verify_alignment`，通过后提交。
6. **避免冗余**：内容与层 README / 组件子文档重复的部分只留一处（Rule 1）。
